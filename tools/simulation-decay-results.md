# 시뮬레이션의 행별 감쇠 계수 재사용

비교 기준은 `main`의 `ec7768b`입니다. 복사 개선과 숫자형·콜백 native 루프가
이미 적용된 설치본을 같은 Windows 컴퓨터에서 비교했습니다.

## 구현

한 행의 beta가 같으면 사건마다 `exp(-beta * wait)`를 행별로 한 번 계산합니다.
지수 함수 호출은 D×K회에서 D회로 줄고, 성분별 곱셈·합산 순서는 유지됩니다.
사건 선택이 끝난 뒤 더 이상 사용하지 않는 균등 난수 작업 벡터에 계수를 저장해
추가 작업 벡터 할당을 피했습니다. 난수를 다시 생성하거나 소비 순서를 바꾸지 않습니다.

숫자형 동일 감쇠율 모형은 별도 `hawkes_simulate_equal.cpp`를 사용하고,
지원하는 콜백 모형은 기존 콜백 루프에서 계수를 재사용합니다.
기존 일반 숫자형 소스는 그대로 보존했습니다. 같은 GCC에서 컴파일한
그 함수의 코드 섹션 59개가 이전 객체 파일과 모두 일치했습니다.
한 소스에 분기를 추가한 탐색 구현에서 기존 경로의 속도 저하가 관찰돼 분리했습니다.
아래 수치는 최종 분리 구현에서 새로 측정한 값입니다.

지원 범위와 R fallback 판정, 사용자 함수의 기본값, 콜백 전후 RNG 동기화,
초기 행만 요청했을 때의 난수 처리, 우도 엔진 옵션은 유지합니다.
행 내부 서로 다른 beta를 사용하는 기존 경로의 기능을 확장하지 않습니다.

## 정확성

- 직전 설치본과 11개 모형×2개 RNG×4개 출력 크기×3개 seed, 총 264개 조합의
  모든 시뮬레이션 자료와 최종 `.Random.seed`가 `identical()`로 일치했습니다.
- 성능 측정 54쌍과 메모리 측정 6쌍도 자료와 최종 RNG가 정확히 일치했습니다.
- 추가 회귀 검사는 D=1·4, K=16·32·128, 역순 매핑, 서로 다른 행별 beta,
  mark·eta·현재 상태 impact, 초기 행을 포함한 세 크기의 72개 조합입니다.
  R 기준 경로와 전체 반환값·RNG를 비교하고 R/C++ 우도로 강도·성분을 독립 복원합니다.
- 기존 숫자형·서로 다른 감쇠율·콜백 회귀 검사와 지원 밖 모형의 fallback 검사를 유지합니다.
- 별도 12개 모형과 콜백 6개 모형의 1,000개 사건도 R/C++ 우도로 독립 복원했습니다.
  기록된 강도·성분과 사건당 로그우도의 최대 오차는 0이고 RNG를 소비하지 않았습니다.

## 시간

전체 `hsim()` 호출 시간의 중앙값입니다. 각 버전에서 준비 실행 세 번 후,
수정 전후 순서를 번갈아 세 번 측정했습니다. 1만 사건의 각 측정은 완전한 호출
다섯 번의 호출당 시간입니다. 설치·컴파일·자료 저장·비교·명시적 GC는 제외하고,
다른 무거운 작업과 동시에 실행하지 않았습니다. 작은 모형과 대조군도 포함했습니다.

| 모형 | 사건 수 | 이전 ms | 수정 ms | 배속 |
| --- | ---: | ---: | ---: | ---: |
| 숫자형 D=4, K=8 | 10,000 | 12.77 | 8.12 | 1.57 |
| 숫자형 D=8, K=16 | 10,000 | 48.69 | 30.55 | 1.59 |
| 숫자형 D=4, K=32 | 10,000 | 49.05 | 28.36 | 1.73 |
| 숫자형 D=4, K=128 | 10,000 | 185.51 | 102.68 | 1.81 |
| 숫자형 D=8, K=16 | 100,000 | 442.31 | 273.36 | 1.62 |
| 현재 성분 impact D=4, K=8 | 10,000 | 66.99 | 62.84 | 1.07 |
| rmark D=4, K=8 | 10,000 | 38.90 | 32.36 | 1.20 |
| 무거운 impact D=4, K=8 | 10,000 | 473.34 | 476.99 | 0.99 |
| 숫자형 D=4, K=8 | 100 | 0.438 | 0.402 | 1.09 |
| 숫자형 D=4, K=8, 초기 행만 | 0 | 0.303 | 0.306 | 0.99 |

단변량 1만 사건은 1.972→1.947ms, 기존 서로 다른 beta 대조군은
21.04→20.75ms, `...` R fallback은 496.65→500.93ms였습니다.
이 작은 차이와 무거운 impact의 변동을 개선이나 성능 회귀로 해석하지 않습니다.
콜백 자체의 계산량이 크면 이번 중복 제거의 효과는 제한적입니다.

## 메모리

1만 사건을 별도 새 프로세스에서 모드별 한 번씩 측정했습니다.
누적 R 할당은 `Rprofmem()`이고 C++ 작업 메모리는 포함하지 않습니다.
최대 점유는 할당 추적 없이 실행한 Windows peak working set이며
패키지 로딩과 준비 실행을 포함합니다. 두 지표를 구분합니다.

| 모형 | 누적 R 할당 MiB: 이전→수정 | 최대 점유 MiB: 이전→수정 |
| --- | ---: | ---: |
| 숫자형 D=4, K=8 | 7.10→7.10 | 119.34→119.71 |
| 숫자형 D=4, K=128 | 80.45→80.45 | 208.70→208.70 |
| 현재 성분 impact D=4, K=8 | 18.70→18.70 | 138.98→139.33 |

메모리 감소를 주장하지 않습니다. 전체 반환 이력은 계속 O(size×D×K) 공간을 사용합니다.
