# 숫자형 Hawkes 시뮬레이션의 Rcpp 사건 루프

## 범위

숫자형 `mu`, `alpha`, `beta`, 모든 차원에서 양수인 baseline, 같은 행 안의 동일 감쇠율을 지원합니다. 다변량·비정방 다중 커널과 `type_col_map`, 검증 조건을 만족하는 signed 성분도 포함합니다. 사건 선택, 감쇠, 사건 후 갱신, 횟수·강도 이력 기록을 하나의 C++ 루프로 실행합니다.

함수형 모수, 사건별 callback, `eta`, 사용자 잔차분포, 0 baseline, 서로 다른 행 내부 감쇠율은 기존 R 경로를 사용합니다. 우도용 `emhawkes.engine` 옵션은 바꾸지 않았습니다. 내부 `simulate_hawkes_r()`로 R 경로를 직접 실행할 수 있습니다. 지원 여부와 초기 상태는 난수 scope 진입 전에 확인하며, C++ 실행 중 오류를 잡아 R로 다시 시작하지 않습니다.

## 정확성

기준은 복사를 이미 개선한 `ac880e1f55f6ae18a4c33c8fe32a6928901115df`입니다. 이 커밋과 수정본을 같은 컴퓨터의 별도 라이브러리에 설치했습니다.

- 기존 40개 조건에서 전체 출력 자료·속성·경고·최종 `.Random.seed`가 `identical()`로 일치했습니다. callback이 보관한 인자와 `...`, 초기 상태, 소멸, 사용자 잔차분포도 포함합니다.
- 새 회귀 검사의 552개 조합에서도 전체 출력과 최종 난수 상태가 정확히 일치했습니다. 두 RNG 종류, 세 seed, 네 크기, D=1·2·3·4·8, K=1·D·2D·5, 순서가 바뀌거나 겹치는 유형별 매핑을 검사했습니다.
- 기본 초기화, 0 성분, 비영 `N0`·`Nc0`, 매우 작은/큰 baseline, 기존 seed 유무와 초기 행만 있는 출력도 검사했습니다. 초기 행만 요청하면 seed를 만들거나 바꾸지 않습니다. 실행 중 오류에서도 이미 소비한 난수를 유지하고 재시작하지 않습니다.
- 12개 대표 모형의 1,000개 사건을 R과 C++의 `logLik(infer=TRUE)`로 독립 복원했습니다. 사건 전후 강도·성분과 사건당 우도 차이의 최대 척도 오차는 **0**이었습니다. 별도 23개 모형의 복원과 독립 누적 횟수도 회귀 검사에 포함합니다.
- 17개 성능 조건의 세 반복과 별도 메모리 실행에서도 출력과 난수 상태가 정확히 일치했습니다. 허용오차를 넓혀 통과시킨 비교는 없습니다.

R과 같은 순서로 모든 차원의 지수 후보를 만든 뒤 모든 균등 난수를 만듭니다. 후보 동률은 기존 행 선택 순서를 따릅니다. 행 합계는 R처럼 `long double`로 누적한 뒤 반올림합니다. R이 처음 공유하는 사건 시간·유형 벡터는 native 갱신 전에 분리합니다.

## 병목과 시간

Windows 11 x64, R 4.5.1, Rcpp 1.0.14에서 측정했습니다. 이전 컴퓨터의 수치를 속도 기준으로 사용하지 않았습니다. 수정한 R 기준의 D=4·K=8, 10만 사건 프로파일에서 도착 계산 호출이 전체 표본의 약 43%였고, 나머지는 상태 갱신·기록 등에 분산되어 있었습니다. 과거의 큰 이력 복사 대신 전체 사건 루프를 옮겼습니다. 프로파일의 명목 초 대신 표본 비율을 해석했습니다.

전체 공개 `hsim()` 호출을 준비 실행 후 세 번 측정하고 중앙값을 보고합니다. 수정 전후 순서는 반복마다 바꿨습니다. 설치·프로세스 시작·출력 비교는 제외했으며 측정 중 다른 무거운 작업은 실행하지 않았습니다. 빠른 호출이 0초로 반올림되는 `proc.time()` 대신 고해상도 `Sys.time()` 경과 시간을 사용했습니다. 작은 조건은 완전한 호출을 반복해 호출당 시간으로 환산했습니다. CPU 시간은 별도 원시 자료에 있습니다.

## 메모리

별도 새 프로세스에서 1만 사건을 측정했습니다. 누적 R 할당량은 `Rprofmem()`으로 측정한 합계이며 C++의 작은 작업 벡터 할당은 포함하지 않습니다. 최대 RSS는 Windows 프로세스 전체의 최고 working set으로, 패키지 로딩과 준비 실행도 포함합니다. 두 지표는 서로 다른 값이며 각각 한 번의 별도 실행입니다. 반환 객체 크기는 동일합니다.

## 재현과 제한

기준 커밋과 수정본을 별도 라이브러리에 설치한 뒤 저장소 루트에서 실행합니다. `WORK`는 큰 경로와 프로파일을 보관하는 저장소 밖 경로입니다.

```text
Rscript --vanilla tools/run-native-simulation.R BASE_LIB NEW_LIB WORK OUT
Rscript --vanilla tools/check-native-simulation.R NEW_LIB OUT
```

[시간 원시 자료](native-simulation-results/measurements.csv), [시간 요약](native-simulation-results/timing-summary.csv), [메모리](native-simulation-results/memory.csv), [기존 조건 비교](native-simulation-results/cross-version-checks.csv), [독립 복원](native-simulation-results/replay.csv), [기준 프로파일](native-simulation-results/base.profile-total.csv), [실행 환경](native-simulation-results/session-info.txt)을 제공합니다.

시간과 메모리는 이 컴퓨터의 측정값입니다. 같은 환경에서 R과 C++의 정확 일치를 검증하며 서로 다른 운영체제 사이의 난수 경로 일치를 새로 보장하지는 않습니다. 전체 출력 이력은 계속 O(size × D × K) 메모리를 사용합니다. 서로 다른 감쇠율, 0 baseline, 마크·잔차분포·callback 가속은 후속 범위입니다. 함수 기본값 바인딩과 analytic gradient 인터페이스는 변경하지 않았습니다.
