# 서로 다른 감쇠율의 숫자형 시뮬레이션

## 구현 범위

행 안에서 `beta`가 서로 다른 숫자형 모형도 전체 Rcpp 사건 루프를 사용합니다. 모든 baseline이 양수이고 `eta`, 사용자 함수·사건 callback·잔차분포가 없는 모형에 적용합니다. 다변량, 비정방 다중 커널, `type_col_map`, 기존 단조성 조건을 만족하는 signed 성분을 지원합니다. 나머지는 기존 R 경로를 유지합니다. 우도용 `emhawkes.engine`과 함수 기본값 바인딩은 변경하지 않았습니다.

기존 R thinning을 그대로 옮겼습니다. 각 차원의 사건 후 강도를 고정 상한으로 사용하고, 지수·균등 난수 쌍을 차원 순서대로 생성하며 기각된 후보도 유지합니다. 모든 행이 동일 감쇠율이면 기존 직접 추출 경로를 유지합니다. signed 검증은 감쇠율별 그룹 합과 누적합을 사용하며 원래 열 순서와 반올림을 보존합니다. `long double`이 `double`과 같은 플랫폼에서는 곱셈과 합산이 융합되지 않게 합니다.

지원 여부와 초기 상태를 난수 생성 전에 판정하며 실행 중 오류를 잡아 R로 다시 시작하지 않습니다. 초기 행만 요청하면 seed를 만들거나 바꾸지 않습니다. 작은 baseline의 역수와 강도 합계가 넘치는 경우에도 R의 경고·오류와 소비한 난수를 유지합니다.

## 병목과 정확성

비교 기준은 직전 native 구현 **`53a5f83483146f8efb5363ac62a871c45a6cc7f6`**입니다. 과거의 이력 복사 문제가 남아 있던 버전을 기준으로 삼지 않았습니다. 같은 Windows x64, R 4.5.1, Rcpp 1.0.14에서 별도 라이브러리에 설치했습니다.

D=4, K=8의 10만 사건 R 프로파일에서는 도착 계산이 표본의 약 40.5%였습니다. 전치, 행 합산, 배열 생성·기록에도 시간이 분산돼 있어 도착 함수만이 아니라 사건 루프 전체를 옮겼습니다. Windows 프로파일의 명목 초를 경과 시간으로 해석하지 않았습니다.

- 기존 40개 조건과 새 회귀 검사 408개 조합에서 출력·속성·최종 `.Random.seed`가 정확히 일치했습니다. 새 검사는 두 RNG, 세 seed, 네 크기와 D=1·2·4·8, 여러 커널 수, 일부 행만 동일한 감쇠율, 순서가 바뀌거나 겹치는 매핑, 반복 감쇠율 그룹, signed·다수 기각 모형을 포함합니다. 기존 동일 감쇠율 검사 552개 조합도 유지합니다.
- 초기화, 비영 `N0`·`Nc0`, 0 성분, 한 행 출력, 극단적 baseline, 허용된 signed 오차 근처의 0·음수 상한, 초기 검증 실패와 사건 후 오류를 검사합니다. callback·잔차분포·0 baseline의 R fallback 검사도 유지합니다.
- 다섯 대표 모형의 1,000개 사건을 R/C++ `logLik(infer=TRUE)`로 독립 복원했습니다. 사건 전후 강도·성분과 사건당 우도 차이의 최대 척도 오차는 **0**입니다. 새로운 허용오차를 도입하지 않았습니다.
- 같은 경로에서 R 난수 호출을 별도로 세었습니다. 다수 기각 모형의 1,000개 사건은 지수·균등 난수를 각각 399,664회 사용했고 기각 후보는 397,664개였습니다. 이 경로도 출력과 최종 seed가 정확히 일치했습니다.
- 시간·할당량·별도 최대 점유량 측정에서도 수정 전후 출력과 최종 seed를 비교합니다. 측정 후 추가한 플랫폼별 반올림 처리는 이 Windows 빌드의 기계어를 바꾸지 않았음을 DLL `.text` 해시로 확인했습니다.

## 시간

설치·컴파일·프로세스 시작을 제외한 전체 공개 `hsim()` 호출입니다. 준비 실행 후 최소 세 번 측정했고 버전 순서를 번갈아 바꿨습니다. 측정 중 다른 무거운 작업을 실행하지 않았습니다. 고해상도 `Sys.time()`으로 잰 중앙값이며 작은 조건은 완전한 호출을 반복해 환산했습니다.

| 모형 | 사건 수 | 53a5f83 | 수정본 | 배속 |
| --- | ---: | ---: | ---: | ---: |
| D=1, K=2 | 10,000 | 0.32350초 | 0.003031초 | 106.7배 |
| D=4, K=8 | 10,000 | 0.46513초 | 0.020638초 | 22.5배 |
| D=8, K=16 | 10,000 | 0.72138초 | 0.086390초 | 8.4배 |
| D=1, K=2 | 100,000 | 3.18248초 | 0.025564초 | 124.5배 |
| D=4, K=8 | 100,000 | 4.71767초 | 0.247185초 | 19.1배 |
| D=8, K=16 | 100,000 | 7.13420초 | 0.781331초 | 9.1배 |
| 다수 기각 D=2, K=4 | 10,000 | 8.86097초 | 0.266856초 | 33.2배 |
| Signed D=2, K=4 | 10,000 | 0.48595초 | 0.006370초 | 76.3배 |

서로 다른 감쇠율의 초기 행만 요청한 경우는 0.176→0.171ms, 10개 사건은 0.529→0.177ms였습니다. 기존 동일 감쇠율 D=4·K=8과 현재 강도 callback의 R fallback은 대조 조건입니다. 기존 단변량 native의 초기 행·10개·100개 사건은 각각 0.156→0.155ms, 0.158→0.159ms, 0.178→0.177ms였습니다. 작은 변동을 별도의 속도 개선으로 주장하지 않습니다.

한 worker는 측정 도구의 주석을 실행 중 수정해 종료 단계에서 구문 오류가 났습니다. 완료로 기록하지 않고 해당 조건의 두 버전을 다시 측정했습니다. 정상 종료·출력·seed 비교까지 완료된 조건만 checkpoint에서 재사용했습니다.

## 메모리와 제한

누적 R 할당량은 `Rprofmem()` 합계이며 C++ 작업 벡터는 포함하지 않습니다. 최대 점유량은 별도 새 프로세스에서 추적 없이 측정한 Windows peak working set입니다. 패키지 로딩·준비 실행도 포함하므로 순수 출력 크기와 다릅니다. 할당 추적 실행에서 기록한 peak는 비교 표에 사용하지 않습니다. 반환 객체 크기는 같습니다.


1만 사건, 별도 실행 각 1회의 결과입니다.

| 모형 | 누적 R 할당 MiB: 이전→수정 | 최대 점유 MiB: 이전→수정 |
| --- | ---: | ---: |
| D=1, K=2 | 2.10→1.15 | 127.7→85.9 |
| D=4, K=8 | 36.74→7.10 | 140.9→91.5 |
| D=8, K=16 | 154.41→23.59 | 174.1→108.5 |
| 다수 기각 | 4.69→2.52 | 127.7→88.4 |
| Signed | 4.69→2.52 | 128.8→88.2 |
| 현재 강도 callback (R) | 51.24→51.24 | 143.0→137.8 |

전체 강도 이력은 여전히 O(size × D × K) 메모리를 사용합니다. 기각 상한을 갱신하거나 다른 도착 알고리즘을 쓰면 기존 seed 경로가 바뀌므로 이번에는 적용하지 않았습니다. 함수형 모수, callback, `eta`, 사용자 잔차분포와 0 baseline의 가속은 별도 범위입니다. 플랫폼 사이의 동일 경로를 새로 보장하는 작업은 아니며 각 플랫폼에서 R 기준과 비교합니다.

## 재현

```text
Rscript --vanilla tools/run-simulation-unequal.R BASE_LIB NEW_LIB WORK OUT
Rscript --vanilla tools/check-simulation-unequal.R NEW_LIB OUT
```

`WORK`는 큰 경로·프로파일·로그를 보관하는 로컬 폴더입니다. 완료된 동일 설치본의 비교를 이어갈 때만 마지막 인자로 `resume`을 추가합니다. 계산 코드를 변경했다면 새 `WORK`·`OUT`에서 시작해야 합니다.
