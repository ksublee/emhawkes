# 사용자 함수 시뮬레이션 가속

비교 기준은 `main`의 `36e79e5`입니다. 복사 개선과 숫자형 native 루프가 이미
적용된 버전을 같은 Windows 컴퓨터에서 다시 측정했습니다. 설치된 기준
패키지의 R 함수 본문·인자 목록도 해당 커밋과 일치하는지 확인했습니다.

## 적용 범위

- 기존 `setting()`이 숫자로 확정한 `param` 전용 `mu`, `alpha`, `beta`는
  기존 숫자형 루프를 사용합니다. 함수 재평가나 기본값 바인딩을 추가하지 않습니다.
- 모든 baseline이 양수이고 각 행의 감쇠율이 같으면, 숫자형 `eta`, 사건 문맥을
  요청하지 않는 `rmark`, 현재 `lambda_component_n`만 요청하거나 문맥을
  요청하지 않는 `impact`도 지원합니다. 선택하지 않은 인자는 원래 기본값을 유지합니다.
- 사용자 함수는 R에서 실행합니다. mark의 대입과 impact의 열 선택도 R에서
  처리해 기존 재활용·경고·오류 의미를 보존합니다. 반환값은 실수형 mark와 성분이어야 합니다.
- 사건별 baseline, 다른 사건 인자·전체 이력·`...`, 사용자 잔차분포, 0 baseline,
  서로 다른 감쇠율과 콜백을 함께 쓰는 모형은 R로 실행합니다.
  사건 생성 난수는 지원 판정 후 소비하며, 소비 후 R로 재시작하지 않습니다.
  설정 단계의 사용자 함수 호출과 그 난수 소비 순서는 기존대로 유지합니다.

기존 숫자형 루프와 콜백 루프는 별도 소스에서 컴파일하고 상태 합산·검증 헤더를
공유합니다. 공통 템플릿을 사용한 탐색 구현에서 숫자형 대조군의 성능 회귀를
발견해 분리했습니다. 최종 숫자형 함수 본문은 이전과 같고, 동일 GCC에서
객체 파일의 코드 섹션 59개가 모두 바이트 단위로 일치했습니다.

콜백 전후에 RNG 상태를 저장·복구하며 오류에도 적용합니다. 콜백 루프는
Rcpp의 중첩 RNG 카운터를 점유하지 않는 RAII scope를 사용해, 콜백 안에서 다시
native 시뮬레이션을 호출하는 경우도 처리합니다. impact마다 새 성분 행렬을
전달하며 beta에서 상속한 이름·속성과 보관된 인자 값을 유지합니다.

## 정확성

기존 숫자형 552개, 서로 다른 감쇠율 408개, 추가 콜백 744개 조합에서
전체 출력과 최종 `.Random.seed`가 `identical()`로 일치했습니다.
콜백 조합은 D=1·2·4, K=D·2D, 역순 매핑, 두 RNG,
세 seed, 초기 행만 포함하는 네 크기를 사용합니다. 기존 signed 성분의
콜백 회귀 검사도 유지했습니다.

추가로 기본 초기화와 모수 함수 호출 횟수·순서, 기본값의 지연 평가,
현재 성분의 이름·속성·보관·수정, 숨은 난수, 세 정규 난수 생성법,
`.Random.seed` 직접 조회, 경고·오류·중첩 호출 후 난수 상태를 검사했습니다.
지원·fallback 분기는 native wrapper 추적으로 확인했습니다.

직전 설치본과의 기존 진단 40개, 시간 측정 57쌍, 할당·최대 점유 측정
12쌍도 출력과 최종 seed가 정확히 같았습니다. 여섯 모형의 1,000개 사건을
기존 R/C++ `logLik(infer=TRUE)`로 독립 복원한 사건 전후 강도·성분과
사건당 로그우도의 최대 차이는 모두 0이며 난수를 소비하지 않았습니다.

## 시간

D=4, K=8이며 전체 `hsim()` 시간입니다. 각 버전에서 준비 실행 세 번 후
실행 순서를 번갈아 세 번 측정한 중앙값입니다. 1만 사건 조건의 각 측정은
완전한 호출 다섯 번의 호출당 시간입니다. 설치·컴파일·프로세스 시작은 제외하고
다른 무거운 작업과 동시에 측정하지 않았습니다. 탐색 구현의 측정값은 제외하고
최종 분리 구현에서 전체 조합을 새로 측정했습니다.

| 모형 | 사건 수 | 이전 초 | 수정 초 | 배속 |
| --- | ---: | ---: | ---: | ---: |
| param 전용 baseline | 10,000 | 0.43319 | 0.01298 | 33.4 |
| 현재 성분 impact | 10,000 | 0.49808 | 0.06830 | 7.3 |
| 인자 없는 rmark | 10,000 | 0.45756 | 0.03862 | 11.8 |
| rmark와 eta | 10,000 | 0.51982 | 0.03974 | 13.1 |
| eta만 지정 | 10,000 | 0.45769 | 0.01400 | 32.7 |
| 무거운 impact | 10,000 | 0.91314 | 0.48918 | 1.9 |
| 현재 성분 impact | 100,000 | 4.91462 | 0.71025 | 6.9 |
| 인자 없는 rmark | 100,000 | 4.59830 | 0.42101 | 10.9 |

현재 성분 impact의 100개 사건은 5.216→1.086ms, rmark는 4.978→0.730ms였습니다.
초기 행만 있는 impact 모형은 0.344→0.368ms로 준비 비용이 약 24μs 늘었습니다.
기존 숫자형 모형의 초기 행·10개·100개 사건은 각각
0.303→0.311ms, 0.323→0.327ms, 0.436→0.451ms였습니다.
1만 사건의 기존 동일·상이 감쇠율 숫자형 대조군은 각각 0.01309→0.01276초,
0.02364→0.02089초였습니다. 이 대조군의 작은 변동은 별도의 개선으로 주장하지 않습니다.
`...`와 관측 상태를 사용하는 R fallback 대조군도 약 0.5·0.6초로 유지됐습니다.

## 메모리와 제한

1만 사건, 각 모드에서 별도 새 프로세스 한 번의 측정입니다.
누적 할당은 `Rprofmem()`이며 C++ 작업 벡터를 제외합니다.
최대 점유는 할당 추적 없이 실행한 Windows peak working set으로,
패키지 로딩·준비 실행을 포함합니다. 두 값을 서로 대신 사용하지 않습니다.

| 모형 | 누적 R 할당 MiB: 이전→수정 | 최대 점유 MiB: 이전→수정 |
| --- | ---: | ---: |
| 현재 성분 impact | 51.24→18.70 | 137.13→138.66 |
| 인자 없는 rmark | 36.74→7.10 | 135.54→114.35 |
| rmark와 eta | 45.44→7.10 | 137.54→115.02 |
| 무거운 impact | 329.41→296.86 | 161.36→168.80 |
| 기존 숫자형 | 7.10→7.10 | 112.20→112.59 |
| `...` R fallback | 51.24→51.24 | 137.12→137.69 |

누적 할당이 줄어도 최대 점유가 줄지는 않았습니다. 최대 점유 한 번의 수치는
기술적 관찰이며 일반적인 감소율을 보장하지 않습니다. 전체 반환 이력은 여전히
O(size × D × K) 공간을 사용합니다. 무거운 사용자 계산과 전체 문맥·상이 감쇠율
콜백의 가속은 별도 검토 범위입니다. 플랫폼 간 난수 경로의 동일성을 새로
보장하지 않으며 각 플랫폼의 기존 R 경로와 비교합니다.

## 재현

```text
Rscript --vanilla tools/run-simulation-callback.R BASE_LIB NEW_LIB RAW OUT
Rscript --vanilla tools/check-simulation-callback.R NEW_LIB OUT
```
