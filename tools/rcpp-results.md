# Rcpp 구현 검증 기록

2026년 10월 11일, Windows 11, R 4.6.0, Rcpp 1.1.2, GCC 14.3.0에서 검증했다. CPU는 Intel Core Ultra 7 356H다. 아래 시간은 이 환경의 측정값이며 다른 자료나 장비의 배속을 보장하지 않는다.

## 구현 범위

숫자형 `mu`, `alpha`, `beta`, `eta`를 사용하는 Hawkes 모형의 로그우도와 추론을 C++로 계산한다. 비정방 multi-kernel, 사건 유형별 커널 매핑, 행 안에서 서로 다른 감쇠율, signed 성분을 지원한다. 사건 루프와 잔차 누적을 한 native 호출로 처리한다.

`hfit()`은 기존 모수 공유, 후보 복원, 생성자 검증, 초기화, `maxLik` 최적화를 사용하며, 후보의 우도 계산에 새 엔진을 연결한다. 반환값의 이름과 차원도 유지한다. 초기 상태와 관측 자료는 R에서 정규화하고 native 경계에서도 길이·차원·인덱스를 검사한다. 입력 객체를 직접 수정하지 않으며 난수를 사용하지 않는다.

함수형 모수, 사용자 impact·mark 밀도, FRPP는 기존 R 계산을 사용한다. 사용자 클래스가 있는 숫자 모수, 관측 벡터, 커널 매핑도 R의 연산·부분 선택 메서드를 보존하기 위해 R 경로로 보낸다. 시뮬레이션과 해석적 gradient의 C++ 이식은 이번 범위에 포함하지 않았다.

## 기존 결과와 비교

C++ 소스를 추가하기 전에 R 패키지를 별도 라이브러리에 설치하고 결과를 저장했다. 일반·marked·multi-kernel·signed 모형과 기본 초기화의 우도, 강도 경로, 성분 경로, 잔차를 비교했다. 같은 시작점과 제약을 사용한 단변량 및 multi-kernel 추정도 비교했다. Multi-kernel 추정에서는 서로 다른 네 감쇠 모수를 고정하고 두 baseline과 공유 excitation을 추정했다.

| 비교 대상 | 이 환경에서 관측한 최대 절대 차이 |
| --- | ---: |
| 로그우도·추론의 모든 숫자 값 | 0 |
| 추정 후 로그우도 | 0 |
| 추정 모수 | 0 |
| 추정 gradient | 0 |
| 추정 Hessian | 0 |

R 강제 실행, C++ 강제 실행, 자동 선택 모두 저장한 결과와 일치했다. 두 추정의 수렴 코드는 0이었다. 비트 단위 일치를 모든 플랫폼의 요구조건으로 삼지는 않는다. 다른 환경에서는 회귀 테스트의 허용 오차와 달성 우도를 함께 확인한다.

기존 전체 사건 이력과 독립 수치적분 테스트도 통과했다. 따라서 R과 C++가 서로 일치하는 것만으로 검증을 끝내지 않았다.

## 속도

1,000·10,000·100,000개 사건의 세 숫자형 모형을 비교했다. 첫 초기 행은 사건 수에 포함하지 않는다. 준비된 우도, 자료 검증을 포함한 공개 `logLik()`, 추론을 따로 측정했다. 각 경로를 먼저 실행하고 빠른 호출은 batch로 묶었다. R과 C++ 순서를 번갈아 3회 측정한 호출당 elapsed time의 중앙값이다. 최종 측정은 컴파일이나 다른 검사를 동시에 실행하지 않고 수행했다.

다음은 100,000개 사건의 준비된 우도와 추론 결과다.

| 모형 | 계산 | R | C++ | 배속 |
| --- | --- | ---: | ---: | ---: |
| 단변량, 커널 1개 | 우도 | 0.540초 | 0.0138초 | 39.3배 |
| 2차원, 커널 열 2개 | 우도 | 0.590초 | 0.0388초 | 15.2배 |
| 2차원, 커널 열 4개 | 우도 | 0.630초 | 0.0725초 | 8.7배 |
| 단변량, 커널 1개 | 추론 | 1.790초 | 0.0156초 | 114.6배 |
| 2차원, 커널 열 2개 | 추론 | 1.900초 | 0.0425초 | 44.7배 |
| 2차원, 커널 열 4개 | 추론 | 1.940초 | 0.0775초 | 25.0배 |

자료 검증을 포함한 공개 우도 호출의 배속은 같은 순서로 32.6배, 13.9배, 8.9배였다. 27개 큰 자료 측정에서 우도와 전체 추론 결과의 최대 절대 차이는 모두 0이었다.

추정 시간은 실제로 시뮬레이션한 2,000개 사건에서 별도로 측정했다. 최적화, 후보 객체 구성, 수치 미분과 최종 Hessian 계산을 포함했다. Multi-kernel 예제는 감쇠 모수를 고정했다.

| 추정 모형 | R | C++ | 배속 | 우도 평가 횟수 R / C++ |
| --- | ---: | ---: | ---: | ---: |
| 단변량 | 1.490초 | 0.0700초 | 21.3배 | 126 / 126 |
| 2차원 multi-kernel | 4.430초 | 0.5900초 | 7.5배 | 328 / 328 |

두 추정의 모수와 달성 우도 차이는 0이었다. 평가 횟수는 별도의 시간 측정 밖에서 기록했으며, 우도 계산 전 거절된 후보는 포함하지 않는다.

작은 자료에서는 native 호출과 입력 준비 비용이 상대적으로 크다. 사건 한 개의 공개 우도는 R과 C++에서 단변량 약 0.044ms와 0.054ms, multi-kernel 약 0.046ms와 0.056ms였다. 세 모형의 공개 우도에서 C++가 약 5–10µs 느렸다. 사건 열 개에서는 공개 우도가 약 1.3–1.8배, 추론이 약 4.7–5.6배 빨랐다. 작은 자료의 18개 비교에서도 계산 결과 차이는 모두 0이었다.

CSV 원자료는 [우도·추론 시간](rcpp-results/likelihood-timings.csv), [추정 시간](rcpp-results/fit-timings.csv), [작은 자료 시간](rcpp-results/small-timings.csv), [수정 전 결과 비교](rcpp-results/comparison.csv)에 저장했다.

## 검사 결과와 범위

소스 패키지 빌드와 `R CMD check --no-manual`은 `Status: OK`로 끝났다. 오류, 경고, NOTE는 모두 0개다. 예제와 vignette 재빌드도 통과했다. [검사 로그](rcpp-results/R-CMD-check.log)와 [실행 환경](rcpp-results/session-info.txt)을 함께 저장했다.

기존 6개 테스트와 새 `native-engine.R`, `native-fit.R`을 자동 선택과 R 강제 실행에서 모두 실행했다. 새 테스트 안에서는 C++를 명시적으로 강제해 비교했다. 서로 다른 차원과 비정방 행렬, 중복·순서 변경 매핑, mark, signed 성분, 0 구간, 극단적인 척도, `NaN`·`-Inf`, 초기화, 빈 잔차, callback 실행 순서, 입력 불변성, 난수 상태, 잘못된 native 인덱스를 점검했다. 두 `reduced` 설정의 추정과 사용자 gradient·Hessian 전달도 확인했다.

Windows의 로컬 검사 결과다. Windows·macOS·Linux와 R release·devel·oldrel용 CI를 추가했으며 원격 실행 결과는 아직 확인하지 않았다. 함수형·상태 의존·FRPP 모형의 성능 개선은 이번 측정으로 주장하지 않는다.

## 재현 방법

현재 소스를 설치한 뒤 저장된 [측정 도구](benchmark-rcpp.R)를 실행한다.

```r
options(emhawkes.engine = "auto") # 지원되는 숫자형 모형에 C++ 사용
options(emhawkes.engine = "r")    # R 기준 계산
options(emhawkes.engine = "cpp")  # 지원하지 않는 모형은 오류로 알림
```

```text
Rscript tools/benchmark-rcpp.R <output-directory>
Rscript tools/benchmark-rcpp.R <output-directory> 2,11 likelihood
Rscript tools/benchmark-rcpp.R <output-directory> 1001 fit
```

수정 전 패키지의 별도 라이브러리와 결과를 만들 수 있으면 [check-rcpp.R](check-rcpp.R)의 `snapshot`과 `compare`를 사용한다. 결과마다 패키지 라이브러리와 `sessionInfo()`를 함께 확인한다. 계산 엔진의 등록과 wrapper는 [Rcpp Attributes](https://www.rcpp.org/pdf/Rcpp-attributes.pdf)를 사용하며, 설치 중이나 로딩 중의 즉석 컴파일은 사용하지 않는다.
