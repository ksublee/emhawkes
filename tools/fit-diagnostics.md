# 확장 예제의 추정 진단

이 문서는 수정 전 추정 결과의 진단 기록입니다. 이후 Hawkes의 최종 Hessian과
표준오차를 안정화했습니다. [후속 결과](hawkes-standard-errors.md)를 참고하세요.
수정 전 계산은 아래 재현 명령 끝에 `maxLik`를 지정하여 확인할 수 있습니다.


2026-10-13에 `vignettes_ext/extended_example.Rmd`의 네 예제를 재현했습니다.
기준 코드는 `45dae49a0a428ee3cd15450294fd4683e87ce61d`이며, 원래 seed,
관측 자료, 모수 매핑, 초기 상태를 유지했습니다. 환경은 Windows 11,
R 4.6.0, emhawkes 0.9.9, maxLik 1.5-2.2입니다.

## 결과

| 예제 | 원래 로그우도 | `NaN` 표준오차 | 진단 |
| --- | ---: | --- | --- |
| Multi-kernel | 6084.70174869 | `alpha1.1` | 기본 수치 Hessian의 차분 오차. 다른 커널 시작 순서에서 더 높은 우도 발견 |
| Synchronized intensity | -260.62730006 | `kappa`, `eta`, `nu`, `beta` | 기본 수치 Hessian의 차분 오차. 여러 시작점에서 같은 해 확인 |
| Bid-ask price | -1810.89162660 | `xi` | 기본 수치 Hessian의 차분 오차. `xi`는 모형에 실제로 작용하며 국소 곡률 확인 |
| FRPP, two-dimensional | -12407.47373286 | `a`, `ell` | 자료의 residual과 밀도의 이동하는 전환점이 만남. Hessian이 차분 간격에 민감 |

모든 원래 추정의 반환 코드는 0이었습니다. 이 코드만으로 score가 충분히
작거나 표준오차가 신뢰할 만하다고 판단할 수는 없습니다. 세 Hawkes 예제의
수치 Hessian 문제와 FRPP의 비매끄러운 우도 문제는 구분해야 합니다.

원래 추정에서 저장된 미분의 진단값은 다음과 같습니다. Score는 모수 단위에
의존하므로 서로 다른 예제의 값을 같은 기준으로 비교하지 않습니다.

| 예제 | 최대 절대 score | `-H`의 최소 고유값 |
| --- | ---: | ---: |
| Multi-kernel | 0.89073 | -143.75841 |
| Synchronized | 0.00240 | -0.70205 |
| Bid-ask | 0.09057 | -8.15676 |
| FRPP | 0.83005 | -9571.06984 |

이번 작업은 기본 추정값, Hessian, 표준오차 계산을 바꾸지 않습니다.
아래의 재계산 표준오차는 진단용이며, 저장된 결과를 덮어쓰지 않습니다.

## 확인 방법

1. 예제의 원래 추정을 재현하고 `maxLik::objectiveFn(fit)`으로 추정점의
   우도를 다시 계산했습니다.
2. 저장된 score와 Hessian, 모수별 크기를 고려한 중앙 차분, Richardson
   차분을 비교했습니다. 여러 간격에서 같은 결과가 유지되는지 확인했습니다.
3. 허용오차를 줄이고 시작점을 바꿔 우도, score, 모수의 재현성을 비교했습니다.
4. 정보행렬 `-H`의 고유값과 scale을 적용한 조건수를 확인했습니다.
   FRPP에서는 제약의 활성 여부와 단측 미분, profile도 확인했습니다.

매끄러운 예제의 추가 추정에는 순수 모수 함수를 수치 모수로 평가한 별도
진단 함수를 사용했습니다. 실제 저장 objective와 시작점, 원래 추정점,
교란점, 추가 추정점에서 우도가 일치했습니다. Multi-kernel과 synchronized의
차이는 0이었고, FRPP의 별도 진단용 C++ 계산은 최대 약 `1.82e-12`였습니다.
이 계산기는 패키지의 callback 실행 방식이나 FRPP 계산 엔진을 변경하지 않습니다.

## 세 Hawkes 예제: 기본 Hessian의 차분 오차

설치된 maxLik 1.5-2.2의 기본 최종 수치 Hessian은 절대 간격 `1e-6`의
전진 차분을 사용합니다. 큰 합산 로그우도에서 작은 두 번째 차이를 계산하면
유효 숫자를 잃을 수 있습니다. 모수의 크기가 서로 다를 때도 같은 절대 간격을
사용하므로 문제가 커집니다.

원래 Hessian으로 계산한 `-H`에는 음의 고유값이 있었습니다. 역행렬의
대각 원소가 음수인 모수에서 제곱근을 계산하여 `NaN`이 나왔습니다.
음의 분산에 절댓값을 취하거나 고유값을 임의로 보정하는 방법은 쓰지 않았습니다.

모수 크기를 고려한 중앙 차분과 Richardson 차분에서는 세 예제 모두
안정적인 양의 정부호 정보행렬을 얻었습니다. 원래 추정점에서의 비교는 다음과 같습니다.

| 예제·모수 | 저장 표준오차 | 독립 재계산 표준오차 |
| --- | ---: | ---: |
| Multi-kernel `alpha1.1` | `NaN` | 0.35773 |
| Multi-kernel `beta1.1` | 0.03791 | 1.63309 |
| Synchronized `kappa` | `NaN` | 0.15487 |
| Synchronized `eta` | `NaN` | 0.44037 |
| Synchronized `nu` | `NaN` | 0.39985 |
| Synchronized `beta` | `NaN` | 4.73852 |
| Synchronized `theta_p` | 0.01108 | 0.03956 |
| Bid-ask `xi` | `NaN` | 0.83863 |
| Bid-ask `beta` | 0.35535 | 2.87368 |
| Bid-ask `alpha_m` | 0.72098 | 2.34470 |

`NaN`이 없는 표준오차도 크게 달랐습니다. 따라서 `NaN`만 없애는 수정으로는
충분하지 않습니다. 재계산 수치는 점근적 Wald 추론의 전제를 별도로 확인해야 합니다.

### Multi-kernel

원래 추정의 score는 충분히 작지 않았습니다. 더 엄격한 BFGS 추정에서는
원래 시작점, 기존 추정점, 두 교란 시작점이 모두 약 `6084.72004374`에
도달했습니다. 두 커널 그룹의 시작 순서를 바꾸면 더 높은
`6084.98473958`에 도달했습니다.

이때 고정된 `lambda_component0`의 커널별 값은 바꾸지 않았습니다.
따라서 두 해는 단순히 같은 모형의 라벨만 바꾼 결과가 아닙니다.
커널의 모수 순서와 초기 상태의 배분이 함께 영향을 줍니다.
여러 커널 순서를 포함한 시작점 비교가 필요하며, 발견한 해를 전역 최적해로
단정하지 않습니다.

원래 추정점의 scale 적용 정보행렬 조건수는 약 3788입니다.
양의 정부호이지만 약한 곡률 방향이 있고, 특히 빠른 decay의 불확실성이
기존 표준오차보다 큽니다. 이것만으로 구조적 비식별성을 뜻하지는 않습니다.

### Synchronized intensity

원래 추정점, 원래 시작점, 두 교란 시작점의 엄격한 추정은 같은 모수와
우도에 도달했습니다. 로그우도 차이는 약 `1.5e-9`였습니다.
주된 문제는 최적화 위치가 아니라 최종 수치 Hessian입니다.

scale 적용 정보행렬 조건수는 약 1449입니다. 작은 곡률 방향과 넓은
표준오차가 있지만, 확인한 추정점에서 정확한 구조적 비식별성의 증거는
찾지 못했습니다.

### Bid-ask price

세 시작점의 엄격한 추정은 약 `-1810.89161529`에 도달했습니다.
`xi`는 약 1.76479이고 중앙 차분 표준오차는 약 0.83834였습니다.
원래 추정점의 상대 차분 간격 `1e-4`, `3e-4`, `1e-3`에서도
`xi` 표준오차는 0.83865, 0.83863, 0.83863으로 안정적이었습니다.

`xi`는 가격 변화 사건 후 강도 상태의 갱신에 실제로 사용됩니다.
자료에서 354개 해당 사건의 갱신 효과를 확인했으므로, 코드상 소거되는
모수는 아닙니다. 크기를 조정한 정보행렬의 가장 약한 방향은 주로 `xi`이고
조건수는 약 171입니다. 국소적으로 식별되지만 불확실성이 큽니다.

## FRPP: 이동하는 전환점에서의 비매끄러움

`tzexp`의 밀도는 residual `x = a`에서 연속입니다. 그러나 이 전환점의
양쪽에서 미분식이 달라집니다. 모수를 움직이면 전환점도 움직입니다. 이 점은 분포의 support 끝점이 아닙니다.

원래 추정점의 scale 적용 중앙 차분 정보행렬은 간격 `1e-3`에서 최소 고유값이
약 606이지만, `1e-4`에서는 약 -1564, `1e-5`에서는 약 -9315입니다.
Richardson 차분도 안정되지 않았습니다. 큰 간격에서 얻은 양의 정부호
정보행렬만 골라 표준오차로 채택할 근거는 없습니다.

다섯 유효 시작점의 엄격한 BFGS 추정은 로그우도
`-12407.473821`부터 `-12407.473679` 사이에 도달했습니다.
추정 범위는 `a = 0.71781–0.71821`, `ell = 1.63733–1.63800`이었습니다.
Nelder–Mead의 더 좋은 해는 약 `-12407.47367679`이고,
`a = 0.71821511`, `ell = 1.63801314`였습니다.

이 해에서 한 residual과 `a`의 차이는 약 `9.35e-11`입니다.
`a` 방향의 간격 `1e-6` 단측 기울기는 왼쪽 약 +2.3525, 오른쪽 약 -3.6019로,
`a` 방향에서 꺾이는 지점의 국소 최대를 보여 줍니다.
제약은 활성 경계에 있지 않았으며, 밀도·누적분포·분위수·생성기의
모수 사용도 일치했습니다.

계산한 profile 격자에서도 `a ≈ 0.718`, `ell ≈ 1.638` 부근의 우도가 높았습니다.
보조적으로 계산한 score 기반 정보행렬은 양의 정부호였습니다. 그 역행렬에서
계산한 `a`와 `ell`의 상관은 약 0.973이었습니다. 이것을 검증 없이 대체 표준오차로 쓰지 않았습니다.

현재 표본의 추정 위치는 여러 시작점에서 비슷하게 재현되지만,
단순한 관측 Hessian 역행렬 표준오차는 신뢰하기 어렵습니다.
FRPP 전체에서 Wald 추론이 불가능하다는 결론은 아닙니다.
Profile 구간, 모수적 bootstrap 또는 score 기반 추론의 이론과 유한 표본
성능을 별도로 검증해야 합니다. 이번 작업에서는 구간 추정까지 수행하지 않았습니다.

## 재현 도구와 결과 파일

저장소 루트에서 실행합니다. 원래 예제는 특히 FRPP의 추정에 시간이 걸립니다.

```sh
Rscript tools/reproduce-fit-diagnostics.R <output-directory>
Rscript tools/reproduce-fit-diagnostics.R <output-directory> synchronized,bid_ask maxLik
Rscript tools/diagnose-fit.R <fit.rds> <output-directory>
```

`reproduce-fit-diagnostics.R`은 원본 Rmd에서 필요한 대입식만 실행하여
seed, 관측 자료, callback, 초기 상태, 제약을 유지한 원래 fit을 저장합니다.
`diagnose-fit.R`은 저장 objective의 우도를 확인하고, 저장 미분과 여러
중앙 차분 간격의 결과를 CSV로 출력합니다. 모수나 fit 객체를 바꾸지 않습니다.
이 도구만으로 여러 시작점, 제약, 비매끄러움의 검토가 완료되지는 않습니다.

기록한 수치 결과는 [fit-diagnostic-results](fit-diagnostic-results)에 있습니다.
`*-parameters.csv`는 원래 추정점의 표준오차 비교이고 `*-starts.csv`는
추가 시작점의 결과입니다. FRPP의 Hessian CSV에는 부정정 역행렬에서 얻은
단순 제곱근도 `raw_inverse_se_*`로 기록했습니다. 그 수치는 유효한
표준오차로 채택한 결과가 아닙니다.

Multi-kernel과 synchronized는 `pmax(abs(coef), .1)`, bid-ask의 중앙
차분은 `pmax(abs(coef), 1)`, FRPP는 `pmax(abs(coef), .1)`을 scale로 썼습니다.
Bid-ask의 보고된 조건수 171은 `abs(coef)` scale의 값이며, CSV의 비조정
조건수와 다릅니다. Core 시작점 CSV의 score는 상대 간격 `1e-5`의
중앙 차분, 곡률과 조건수는 간격 `1e-3` 또는 Richardson 재계산 값입니다.
모든 고유값은 별도 표기가 없으면 비조정 정보행렬의 값입니다.

## 함께 확인한 저장 결과의 복원 문제

새 R 세션에서 `library(emhawkes)`만 실행한 뒤 저장 fit을 읽으면 maxLik의
S3 메서드가 등록되지 않아 `coef()`와 `fitted_hspec()`이 실패했습니다.
`maxLik`의 namespace import를 추가하여 해결했고, 별도 R 프로세스에서
계수, summary, 공분산, 모형·초기 상태 복원과 우도 재현을 검증했습니다.

관측 자료 보관 문구도 바로잡았습니다. fit의 공개 메타데이터와 별개로,
저장된 최적화 objective의 함수 환경에는 관측 자료가 남을 수 있습니다.
사용자는 자료를 별도로 보관하고 강도·잔차 계산에 명시적으로 다시 전달해야 합니다.

## 변경 사항의 검증

- `R CMD build --no-manual`, `R CMD check --no-manual`: `Status: OK`.
  새 세션 복원 회귀 테스트를 포함한 10개 테스트, 예제, vignette가 통과했습니다.
- 진단 도구의 중앙 미분과 scale 적용 표준오차는 고정 모수를 포함한 해석적
  quadratic 결과와 `1e-7` 이내에서 일치했습니다. 진단 전후 fit은 동일했습니다.
- 벡터형 objective, 저장 Hessian이 없는 fit, `vcov()`가 실패하는 fit에서도
  중앙 차분 진단이 정상 작동했습니다.
- 네 예제의 추출 구성을 확인했고, synchronized 예제를 실제로 다시 실행하여
  독립 재현의 계수·우도와 일치함을 확인했습니다. 저장 fit용 CLI도 통과했습니다.
- Rd와 웹 문서를 동기화하고 검색 JSON 및 변경 파일의 형식을 확인했습니다.
## 후속 작업

1. 매끄러운 Hawkes 우도에 대해 미분 계산의 scale과 간격을 관리하고,
   여러 간격의 안정성·score·정보행렬을 함께 보고하는 추정 인터페이스를 설계합니다.
2. Multi-kernel에서는 커널 시작 순서와 초기 상태를 포함한 다중 시작점 정책을 정합니다.
3. FRPP의 구간 추론은 profile과 bootstrap을 기준으로 따로 검증합니다.

이번 결과는 같은 네 모의 자료와 조사한 시작점에 대한 진단입니다.
전역 최적화나 모든 모형의 식별성을 증명하지 않습니다.
